# 유예-인지 부족정산: 진행 중인 부분정산을 금액 불일치로 오검출하지 않기

## 목표
#2 금액 불일치의 순수 합-비교(`SUM ≠ amount`)에서, **아직 유예 기간이라 나머지 명세가 올 예정인**
부분정산(부족)을 불일치로 오검출하지 않게 한다.

## 배경
#2는 시점을 안 본다. 그래서 원장 1000에 명세가 아직 600만 찍힌 주문을, 그게 T+2 유예 중
'진행 중'인지 정말 '부족'인지 구분 못 하고 무조건 부족으로 잡는다.
- **초과(sum > amount)**는 시점 무관하게 오류 → #2 그대로 둔다.
- **부족(sum < amount)**만 유예-인지가 필요 → 유예 지난 뒤에만 부족으로 본다.

## 범위
- 부족 케이스에만 마감(컷오프) 조건을 추가: `occurred_at < period_end - grace_days`
  (#4 누락 검출과 같은 컷오프. 유예 중이면 부족을 '진행 중'으로 봐주고 제외).
- 초과 케이스는 조건 없이 계속 검출.
- 유예일수는 배치가 데이터로(`settlement_batch.grace_days`) — 설계원칙 1 유지.

## 완료 기준
- [ ] 유예 중 부족정산은 제외, 유예 지난 부족정산만 검출
- [ ] 초과정산은 유예와 무관하게 항상 검출
- [ ] 변이 테스트: 컷오프 직전/정각/이후 × 부족·초과 조합
- [ ] 로직을 뒤집으면 해당 테스트만 red
